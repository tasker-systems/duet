# `duet capture` v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `duet capture melody|rhythm <source>` turns an audio file into an exact `.notes` performance, plus an ABC or `.drums` score, through a streaming chain of synchronous stages.

**Architecture:** A new crate, `duet-capture`. It holds a `Source` (Symphonia), a `Stage` trait with push and finish, DSP stages (prepare, onsets, pitch and notes, hit lanes, timing), and an `assemble` step that turns settled events into a `duet_core::Song`. `duet-cli` gains a `capture` command group that writes the files through the existing writers.

**Tech Stack:** Rust 2024 (workspace `rust-version = "1.100"`); `symphonia` with its `mp3`, `aac` and `isomp4` features (MPL-2.0); `rustfft` and `rubato` (MIT or Apache-2.0); `thiserror` 2. Dev-only: `pyin` 1.2.0 (MIT), and `hound` for writing WAV in tests.

**Spec:** `docs/superpowers/specs/2026-11-14-capture-design.md`. Read it first; every task cites the section it implements. **The plan is an index over the spec, not a summary of it.**

## Global Constraints

- Every crate root declares `#![forbid(unsafe_code)]` (`crates/duet-drums/src/lib.rs:36`; RUST-UNSAFE-1).
- New crate manifests follow `crates/duet-drums/Cargo.toml`: `edition/license/repository/rust-version.workspace = true`, `[lints] workspace = true`, an `include` list, and version `0.2.0`, path-depending on siblings with `version = "0.2.0"`.
- Errors follow `crates/duet-drums/src/error.rs`: a `#[non_exhaustive]` `thiserror` enum, a `Result` alias, and `From<duet_core::Error>` that keeps unknown variants' messages.
- Public open sets are `#[non_exhaustive]` (RUST-API-2): `Error`, the `Event` enum, and public structs.
- Every new dependency passes `cargo deny --locked check sources licenses bans` (spec: *Constraints*).
- No Temper crate and no async runtime in `duet-capture` (spec: *Approaches*, A; *Anti-goals*).
- Tempo is quarter notes per minute everywhere (spec: *Tempo, meter and downbeat*).
- CI's gates, which the full verification runs: `cargo fmt --all --check`, `cargo clippy --locked --all-targets --all-features -- -D warnings`, `cargo doc --locked --no-deps`, `cargo test --locked`, `cargo deny --locked check sources licenses bans`, and `python3 -I .conventions/baseline/tools/conventions.py check` (`.github/workflows/ci.yml:37-118`).
- Tests that run the `duet` binary go in `crates/duet-e2e` (CLAUDE.md).

## Review Focus

Inputs the spec implies but no clause test exercises, most likely to bite first:

1. **Silence, or a take with no detectable notes or hits.** Expect a clear refusal naming the file ("no notes found"), not an empty score or a tempo estimate from nothing. *Pinned in Task 6 and Task 8.*
2. **Stereo, and sample rates other than the analysis rate** (phones record 48 kHz). Expect the same notes as a mono take at the analysis rate. *Pinned in Task 2.*
3. **A take with a single note or hit.** Tempo can't be estimated from one onset. Expect a refusal asking for `--tempo`, never a made-up value. *Pinned in Task 6.*
4. **An output file that already exists.** Expect a refusal naming it, with nothing written. *Pinned in Task 8.*
5. **A very long file.** Expect bounded memory: no stage before assembly holds more than its window. *Pinned in Task 2, with a chunk-size bound.*
